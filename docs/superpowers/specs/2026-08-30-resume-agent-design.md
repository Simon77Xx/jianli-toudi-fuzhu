# 本地简历定制智能体：设计说明

## 1. 目标与边界

### 目标

为用户本人提供一个本地运行的简历投递助手。用户每次提供一份目标岗位 JD 和一套现有简历材料，系统基于真实经历定制一份中文 LaTeX 简历，并用透明、可追溯的评分帮助用户判断是否值得投递。

首要目标是提高算法技术实习岗位的初筛可读性与岗位匹配表达，尤其是 Agent 算法岗位。评分不能承诺面试结果；候选人池、招聘节奏、内推等外部因素不在系统可控范围内。

### 用户与优先级

- 当前用户：985 计算机相关专业本科生，求职目标为算法技术研发实习。
- 岗位优先级：Agent 算法 > 通用算法 > 研发 > CV/多模态 > 后端 > 其他。
- 当前可用性：2026-10-01 起可到岗，每周 5 天，可连续实习 4--6 个月。
- 首版形态：单用户、本地 `localhost` 网页，不需要登录、云端存储或多用户功能。

### 不做的事

- 不编造、猜测或未经用户确认地新增任何事实、指标、技能或项目职责。
- 不把关键词堆砌当成能力证据，且不以虚高分数掩盖能力缺口。
- 不追踪投递结果、笔试、面试或 Offer，也不基于这些历史结果校准模型。
- 不做公网部署、账号体系、多人协作或通用求职平台。

## 2. 输入、配置与本地数据

### 单次输入

页面接受以下输入：

1. 一份包含主 `.tex`、文档类/样式文件、头像和其他编译资源的 LaTeX 项目 ZIP；
2. 当前 PDF 简历，用于与编译结果做视觉核验；
3. 一份直接粘贴的纯文本 JD；
4. 可选的“读取 GitHub 证据”开关，默认关闭。

ZIP 是必需的完整项目包；仅上传主 `.tex` 不能可靠满足 `resume.cls`、图片等依赖的本地编译需求。

### 模型配置

配置仅从本地 `.env` 读取，页面不展示、保存或传输密钥。项目提供 `.env.example`，并通过 `.gitignore` 排除 `.env`。

首版支持两种协议：

- OpenAI 兼容 API；
- Anthropic 兼容 API。

配置项至少包含协议类型、Base URL、API Key 和模型名。这样可使用 DeepSeek、Qwen，以及 NVIDIA Integrate 等兼容网关。每次模型调用仅发送完成本次分析所需的简历、JD 与用户确认事实。

### 本地事实库

用户在页面中明确确认的事实可保存至本地事实库，记录事实内容、来源、确认时间和适用范围，供下一份 JD 复用。密钥不进入事实库。未确认的模型推断、GitHub 推断与 JD 要求不得成为事实库内容。

用户已确认的基准事实包括：

- 浙江中控信息产业股份有限公司 AI 算法实习：2026-07-01 至 2026-09-30；
- 2026-10-01 起可到岗，每周 5 天，可连续实习 4--6 个月；
- 简历中文为主，保留头像和生日，不保留籍贯，最终限制为 1--2 页且不得超过 2 页。

## 3. 用户流程

```text
上传 LaTeX ZIP 与 PDF + 粘贴一份 JD
                |
读取并提取简历真实证据与 LaTeX 结构
                |
（可选）读取公开 GitHub README/关键代码
                |
拆解 JD：硬门槛、核心能力、加分项、评测偏好
                |
映射：已有证据 / 需确认 / 暂无证据
                |
页面内逐题追问，最多 5 个关键问题
                |
定制 LaTeX：重排、突出、改写、删弱相关项
                |
XeLaTeX 编译与 1--2 页质检，必要时自动压缩
                |
前端展示结果；用户一键下载投递包
```

缺口追问必须一次展示一题，答案提交后再继续。最多 5 题；超过上限或用户未确认时，系统使用现有证据继续生成，但不能把缺口写入简历。

## 4. 功能模块与职责

### 4.1 本地网页

采用 Python + Gradio 实现本地网页。该方案适合个人 MVP，能承载文件上传、长文本 JD、分步问答、报告展示和文件下载，并保留未来替换为 FastAPI + React 的空间。

页面包含：

- 输入区：LaTeX ZIP、PDF、JD 文本与 GitHub 开关；
- 运行区：分析进度、单题追问与回答；
- 结果区：评分、匹配摘要、差异、缺口、建议、编译状态和页数；
- 下载区：定制版 ZIP、PDF（编译成功时）和 Markdown 报告。

### 4.2 证据提取器

从 PDF 与 `.tex` 提取项目、实习、教育、技能、日期、指标、链接及 LaTeX 模块结构。PDF 用作视觉与内容交叉校验，`.tex` 是唯一的可编辑源。

当 GitHub 开关开启时，只读取简历中链接到的公开仓库。读取范围优先为 README、项目配置、目录结构、实验说明和与简历表述直接相关的代码。每个补充证据必须记录仓库 URL 与文件路径；无法核实的内容仍需追问，不可自动写入简历。

### 4.3 JD 分析与证据映射器

将 JD 结构化为：

- 硬门槛：学历、到岗时间、实习时长、语言/框架等；
- 核心职责与问题类型；
- 必备技能与方法；
- 加分项；
- 评测、实验、工程落地偏好。

逐项把 JD 要求归类为“有明确证据”“有待确认的潜在证据”“无证据”。硬门槛必须单独检查；例如当前简历中孤立的 `2026.10` 结束时间应被规范为 `2026.07--2026.09`，避免误读为未来实习。

### 4.4 追问器

追问只针对会显著影响投递判断或可真实提升项目表达的高价值事实，例如：具体职责、实验基线、指标定义、评测方式、可复现链接、到岗条件或确认过的技术细节。

禁止追问引导用户编造；回答不充分时将其保留为缺口。用户确认的回答可经格式化后写入本地事实库。

### 4.5 LaTeX 定制器

在原始项目副本上生成新版本，绝不覆盖上传的源材料。可执行的改动包括：

- 调整摘要、技能、实习与项目模块的顺序；
- 对现有真实项目 bullet 进行岗位导向的改写；
- 突出与 JD 最相关的技术、方法、指标和实验结果；
- 删除或降级弱相关内容；
- 使用用户确认的新增真实信息补强表述。

禁止修改项目/实习的事实边界，禁止生成没有来源的数字、论文、竞赛、技术栈或职责。

### 4.6 编译与篇幅质检

本地使用已安装的 XeLaTeX 编译。自动检查：

- LaTeX 是否能编译；
- 结果页数是否为 1--2 页；
- 是否缺少资源、文档类或依赖包；
- 关键个人事实是否自相矛盾。

如果超过两页，系统自动按优先级压缩：删除弱相关内容、精简 bullet、减少重复技能，再调整有限的排版参数；不得通过缩小到不可读字号或删除关键真实信息来伪造合规。若仍无法通过，展示明确原因，不把结果标为可投递版。

## 5. 评分与投递建议

系统输出两个彼此独立的分数，范围均为 0--100。

### 5.1 投递准备度

衡量定制版简历本身是否可投：事实可信度、硬门槛表达、JD 针对性、信息可读性、LaTeX 编译成功和 1--2 页版式合规等。

- 大于等于 90：标为“可投递”；
- 小于 90：仍生成结果，但标明必须修正的阻碍项。

### 5.2 岗位竞争匹配度

衡量用户真实证据对该 JD 的竞争力，不因表述优化而虚增。

- 小于 50：标为“低优先级/不建议投递”，说明缺少的关键能力或硬门槛；
- 50--69：标为“可尝试”；
- 70--84：标为“较匹配”；
- 大于等于 85：标为“强匹配”。

每项分数必须说明扣分原因、已用证据及其来源。分数是透明的简历/JD 竞争力估计，而非面试承诺。

## 6. 前端结果与下载

完成后，所有核心内容首先在页面展示：

1. 给 HR / AI 初筛最容易识别的一段中文匹配摘要；
2. 投递准备度、岗位竞争匹配度、阈值状态和证据理由；
3. 修改前后差异，包括模块/项目排序、摘要、技能和 bullet 改写理由；
4. 未覆盖缺口及其对投递建议的影响；
5. 面向未来 4--6 个月的补强建议；
6. 编译状态、页数与任何质检警告。

页面提供下载按钮，下载内容为：

- `resume-tailored.zip`：可直接上传 Overleaf 的完整定制项目；
- `resume-tailored.pdf`：仅在本地编译成功时提供；
- `report.md`：完整评分与改动报告。

同一投递包也保存在本地 `output/<JD 标识>-<时间戳>/`，便于找回，不覆盖原始 ZIP。

## 7. 异常处理

| 场景 | 系统行为 |
| --- | --- |
| ZIP 缺少 `.tex`、类文件或图片资源 | 停止编译阶段，前端列出缺失文件与修复方式。 |
| PDF 与 `.tex` 内容明显矛盾 | 标为可信度风险，优先追问；未确认前不改写冲突事实。 |
| API 配置缺失、连接失败或模型输出不符合结构 | 前端显示可操作错误，不改动原文件，不输出虚假成功结果。 |
| GitHub 不可访问或证据不足 | 忽略该外部证据，继续使用简历与已确认事实。 |
| 追问达到 5 题 | 终止追问，未确认项作为缺口，继续生成。 |
| 编译失败或无法压缩至两页 | 保留中间产物与编译日志，前端明确标记“不可投递”，不产出虚假的成功 PDF。 |

## 8. 验收标准

首版完成应至少满足：

1. 可在本机启动一个 `localhost` 网页；
2. 可上传完整 LaTeX ZIP 和 PDF、粘贴一份 JD；
3. 可通过 `.env` 接入 OpenAI 兼容及 Anthropic 兼容 API；
4. 可在页面中完成最多 5 个追问；
5. 可生成且不覆盖原始材料的定制 LaTeX 项目；
6. 可使用 XeLaTeX 编译，并自动把合格结果控制在 1--2 页；
7. 可在页面查看双评分、摘要、差异、缺口和补强建议；
8. 可下载 Overleaf ZIP、成功时的 PDF 和完整报告；
9. 不会在没有用户确认的前提下把推测内容写入简历。
